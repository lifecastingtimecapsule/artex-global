# 回答待ち・繰り返しを止める対策とプロンプトの使い方

更新日：2026-11-06。このデスクトップ版への追加対策。上流標準機能と混同しないでください。

## 今回の原因

タスク1では不足条件を理由に保留し、その保留を引き継ぐ意図を次々に作っていました。ローカル `agent/planner.go` の指示には、目標未達かつ実行中・待機中の意図がなければ必ず新しい意図を作る、という条件があり、回答待ちの例外がありませんでした。テンプレートの質問指示だけでは、この再計画を止められませんでした。

## 追加する対策

- **回答待ち**：planner/workerに `wait_for_user(question)` を必ず使用可能な停止専用ツールとして追加。質問・不足情報を記録し、既存のタスク全体の一時停止処理で実行中の処理をキャンセルし、停止を保存する。ツール使用の判断自体はモデルに依存します。
- **指示の矛盾解消**：必ず新しい作業を作る指示へ、入力・許可不足時は新規作業を作らず停止する例外を追加。カスタムの役割プロンプトにも実行時に共通ルールを補足する。
- **同一作業の再登録抑止**：plannerは同一タスクの直近200意図と、空白・大小文字を正規化した同じ要約／同じ対象資産の組合せを比較し、既存IDを再利用する。意味の近い言い換えや同時挿入まで完全に検知するものではない。人による既存ワーカーへの追加指示は別操作。
- **進展のない計画の抑止**：新しい実作業の成功結果がない状態で3回の計画機会が続き、実行中・待機中の意図がない場合、4回目の計画AI呼び出し前に一時停止。事実の書き込み・引継ぎ・グラフ参照だけを進展と数えない。同じツールの同じ結果も数え直さない。動いているワーカーをこのカウンターだけで中断しないため、全てのループの完全検知を保証しない。
- **13テンプレート**：保存済みの目標末尾に共通停止ルールを追記。既存タスクへテンプレート変更は自動反映されないが、今回の実行時ルールとエンジンの対策は再構築後のplanner/workerに適用される。

## 停止後の使い方

1. セッションとシステムの記録で「自動一時停止」と不足情報を確認する。
2. 調査対象・許可範囲・外部AIへの提供可否など、本人が判断できる情報をタスクの会話へ補足する。秘密値を貼らない。
3. 時間や費用の希望は、強制設定と目安を分けて説明する。実装されていない上限を設定済みと書かない。
4. 必要な情報が揃ったと人が確認してから明示的に再開する。回答しただけでは自動再開しない。
5. 同じ質問で再び止まる場合は、再開を繰り返さず、質問と設定の矛盾を確認する。

### 補足する依頼文の例

```text
対象：提供したコードの指定フォルダーのみ。
実施範囲：コードの読み取りと根拠の整理。対象コードの実行・外部サイト診断・変更・メール送信はしない。
利用権限・外部AIへの提供可否：［本人が確認して記入］
時間・費用：［目安と強制設定の有無を区別して記入］
目的：確認した範囲の問題候補と根拠、未確認事項を報告する。問題が見つからなくても安全保証はしない。
不足情報があれば一度だけ質問して wait_for_user で停止。回答待ちや上限資料の確認を新たな作業として繰り返さない。
```

## README・他のARTEXで確認できたこと

- [artex-global日本語README](https://github.com/jiwoochris/artex-global/blob/main/README.ja.md)：モデル設定、出力言語、並行度、planner/workerの役割、閉じた探索ループ、他ワーカーのトレース参照、共有Todoの説明がある。主に導入と仕組みの説明で、今回の13種類に相当する用途別の営業・簡易・全体調査テンプレート集や、回答待ちの確実な自動停止手順は確認したREADME内には見当たらなかった。
- [ScopeWeaver README](https://github.com/cskwork/scopeweaver)：派生版でも、イベント駆動のplanner、共有Todo、実行の重複を避けるための記録参照、手動の再検証担当のプロンプト・実行予算設定について説明がある。再検証担当の予算という記載を、タスク全体の円建て強制上限の保証と読まない。
- [BaaRai/ARTEX RSI.md](https://github.com/BaaRai/ARTEX/blob/main/RSI.md)：自己改善・将来の最適化作業の契約を扱う別資料。今回の回答待ちループへの完成済み修正や一般利用者向けの依頼文マニュアルとして扱わず、コードの取り込みもしていない。

調査対象は公開READMEと該当ドキュメントの確認範囲に限る。他の全フォーク・全Issue・全ソースを監査したわけではない。

## 100円について

今回の対策は待機ループの抑止であり、円建ての強制予算制限は未実装。無進展を検知するまでにAPI利用が発生し、正常な進捗が続けば費用も増える。以前の5分監視は休止のままで、今回の停止判定のために別のAIを定期実行しない。小さい対象・短い時間・少ない並行度から再開し、必要なら別途、送信前予約を含む予算制限を実装する。
